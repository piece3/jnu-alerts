# 전컴 공지 모아보기 (jnu-alerts)

전남대 전자컴퓨터공학부와 관련 사업단 게시판을 한 번에 긁어서
**소스별 대시보드**(`dashboard.html`) 하나로 보여준다.

## 폰 앱 (웹앱)

GitHub Actions가 매일 08시·18시(한국시간)쯤 `scrape.py`를 돌려서 GitHub Pages에 올린다.
PC가 꺼져 있어도 갱신된다.

- **설치(안드로이드)**: 크롬으로 Pages 주소를 열고 → 메뉴(⋮) → **앱 설치**(또는 홈 화면에 추가).
- **새로고침**: 앱 상단의 `새로고침` 버튼이나 화면을 아래로 당기기. 가장 최근 수집본을 다시 받는 것이고,
  그 순간 게시판을 긁는 건 아니다.
- **지금 바로 수집**: GitHub 레포 → Actions → `공지 수집 + 배포` → Run workflow (약 1분 뒤 반영).
- **오프라인**: 마지막으로 본 화면이 그대로 뜬다.
- 수집 시각 옆에 `(오래됨)`이 붙으면 36시간 넘게 갱신이 안 된 것 → Actions 탭에서 실패 여부 확인.
- 주기 변경: `.github/workflows/update.yml`의 `cron` 두 줄(UTC 기준, 한국시간 − 9시간).

## 구성

| 파일 | 역할 |
|---|---|
| `scrape.py` | 실행 진입점. 모든 소스 수집 → `data.json` 저장 → `dashboard.html` 생성 |
| `sources.py` | 소스 목록 + 게시판 유형별 파서 (여기만 고치면 소스 추가/삭제) |
| `template.html` | 대시보드 HTML 틀 (`/*__DATA__*/` 자리에 데이터가 주입됨) |
| `dashboard.html` | **결과물.** 더블클릭해서 브라우저로 열면 됨. 배포 시 `index.html`이 된다 (git에는 안 올림) |
| `data.json` | 수집 원본 + 각 글의 `first_seen`(최초 발견일, NEW 뱃지 기준). Actions가 수집할 때마다 커밋 |
| `.github/workflows/update.yml` | 예약 수집 + Pages 배포 워크플로 |
| `manifest.webmanifest`, `sw.js`, `icons/` | 앱 설치용 설정 · 오프라인 캐시 · 아이콘 |
| `refresh.bat` | **PC에서 수집 → dashboard.html 열기**. 바탕화면 바로가기가 이걸 실행 |
| `last_run.log` | 마지막 실행 로그 (소스별 건수/실패 여부) |

## PC에서 수동 실행 (바탕화면 바로가기)

바탕화면의 **`전컴 공지 새로고침`** 아이콘을 더블클릭하면:
검은 창이 잠깐 떴다가 → 최신 공지를 긁고 → `dashboard.html`이 브라우저에 열린다 (약 15초).

바로가기 없이 직접 (이 폴더에서):
```
python scrape.py      # 또는 refresh.bat 더블클릭
```

> PC에서 돌리면 로컬 `data.json`이 바뀐다. 폰 앱의 기준은 GitHub 쪽 `data.json`이므로
> 로컬 변경분은 커밋하지 않는 게 낫다(`git checkout data.json`으로 되돌리면 됨).

> 바로가기 다시 만들기(경로 옮겼을 때 등):
> `refresh.bat` 우클릭 → 보내기 → 바탕 화면(바로 가기 만들기)

### 소스 추가/삭제

`sources.py`의 `SOURCES` 리스트에서 항목을 지우거나 추가한다.
같은 CMS를 쓰는 새 게시판이면 `kind`만 맞추면 된다(`k2web`/`jnu`/`kboard`/`www`/`gnuboard`).
전혀 다른 구조면 `sources.py`에 파서 함수를 하나 더 만들고 `PARSERS`에 등록.

## 대시보드 사용법

- **마감 임박**: 제목에 `~9/18`, `~09.04.`, `9월 18일까지` 같은 표현이 있으면 자동으로 D-day 계산. 30일 이내만 표시.
- **분류 필터**: 제목 키워드로 공지 / 공모전·대회 / 학사·장학 / 채용·인턴 자동 분류.
- **소스 박스**: 새 글(NEW)이나 14일 내 마감이 있으면 펼친 상태로, 아니면 접힌 상태로 시작.
- **정렬**: 소스 안에서 고정공지(📌) → 최신순.
- **NEW 뱃지**: 이번 수집에서 처음 발견됐고(≤4일), 글 자체도 21일 이내인 항목.
- **STALE 뱃지**: 그 소스 수집이 실패해서 직전 데이터를 그대로 보여주는 중.

## 의존성

`requests`, `beautifulsoup4`, `lxml` (이미 설치돼 있음). 재설치가 필요하면:

```
python -m pip install -r requirements.txt
```

## 주의

- 개인적으로 공지를 모아보는 용도. 각 사이트에 부담을 주지 않도록 요청 간 0.6초 간격, 소스당 목록 1페이지만, 하루 2회 실행.
- 게시판 구조가 바뀌면 해당 소스만 STALE로 표시되고 나머지는 정상 동작한다. 로그(`last_run.log`)에서 어떤 소스가 깨졌는지 확인 후 `sources.py`의 해당 파서를 수정.
